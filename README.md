# Allur Smart Factory — локальный MVP

Рабочая синтетическая симуляция производства для демонстрации кейса №2. **Все данные, названия участков, мощности, события, причины дефектов, прогнозы и геометрия вымышлены. Это не действующий цифровой двойник Allur и не реальный CAD.** Полный официальный текст задания не был доступен; scope взят из запроса пользователя.

## Запуск на Windows / PowerShell

Нужен Node.js **22.13+** (проверено на 24.19.0) с npm. Сторонних зависимостей нет, `npm install` для запуска не нужен. Node должен быть в PATH. Используем `npm.cmd`, чтобы не менять ExecutionPolicy PowerShell.

```powershell
Set-Location 'C:\Users\ADMIN\Documents\Codex\2026-10-08\referenced-chatgpt-conversation-this-is-an-2\outputs\allur-smart-factory'
node --version
npm.cmd test
if ($LASTEXITCODE -ne 0) { throw 'Тесты не прошли' }
npm.cmd run build
if ($LASTEXITCODE -ne 0) { throw 'Сборка не прошла' }
npm.cmd start
```

В другом окне PowerShell:

```powershell
Start-Process 'http://127.0.0.1:3000'
```

Остановка сервера: **Ctrl+C**. Если порт занят уже запущенным демо, используйте его. Для второго экземпляра:

```powershell
$env:PORT = '3001'
npm.cmd start
# Открыть http://127.0.0.1:3001
```

Сервер доступен только на этом компьютере. `dist` — только клиент; его нельзя запускать двойным кликом или как самостоятельный статический сайт: UI нужен локальный API. После изменения файлов `public` повторите `npm.cmd run build` и обновите страницу. После изменения сервера перезапустите `npm.cmd start`; `npm.cmd run dev` перезапускает сервер автоматически и сбрасывает состояние.

## NVIDIA AI API

Полное демо работает **без ключа и без интернета**. Кнопка «Объяснить прогноз» вернёт локальный разбор с явной причиной fallback.

Для реального NVIDIA-вызова остановите сервер и в его PowerShell-окне введите ключ без отображения на экране и без помещения самого ключа в историю команд:

```powershell
$allurKey = Read-Host 'NVIDIA API key' -AsSecureString
$env:NVIDIA_API_KEY = [System.Net.NetworkCredential]::new('', $allurKey).Password
$env:NVIDIA_MODEL = 'meta/llama-3.3-70b-instruct'
try {
    npm.cmd start
}
finally {
    Remove-Item Env:NVIDIA_API_KEY -ErrorAction SilentlyContinue
    $allurKey = $null
}
```

Альтернатива — локальный `.env`: скопируйте `.env.example` только если `.env` ещё нет, откройте его редактором и заполните `NVIDIA_API_KEY`. Он исключён из Git и сборки. Не вводите ключ в браузер или чат и не включайте `.env` в архив для передачи. Для принудительного offline-демо оставьте ключ пустым в `.env` и уберите `NVIDIA_API_KEY` из окружения.

Вызов: браузер → `POST /api/explain` → Node.js → `https://integrate.api.nvidia.com/v1/chat/completions`. Используется модель `meta/llama-3.3-70b-instruct` (можно изменить `NVIDIA_MODEL`). Передаётся только синтетический снимок. Результат — текстовое объяснение, которое не управляет оборудованием и не меняет численный прогноз.

Защита: сервер слушает 127.0.0.1, проверяет Host/Origin/Sec-Fetch-Site и CSRF для POST, ограничивает запрос 4 КБ, принимает только известные действия, не принимает ключ/endpoint/prompt от клиента. Обычный переход по ссылке с другого сайта открывает только саму страницу `/` (`Sec-Fetch-Mode: navigate`, `Sec-Fetch-Dest: document`); API и статические файлы для чужих сайтов закрыты, проверка Host действует всегда, встраивание во фрейм запрещено.

AI: при настроенном ключе — один запрос к NVIDIA за 10 секунд и один одновременно, таймаут 8 секунд, максимум 64 КБ ответа. Без ключа сеть не используется, поэтому локальное объяснение выдаётся при каждом нажатии без ограничения частоты. Причины fallback различаются и видны в интерфейсе: ключ не настроен, ключ отклонён (401/403), лимит NVIDIA (429), ошибка сервера NVIDIA (5xx), другой HTTP-статус, сеть, таймаут, некорректный ответ, локальное ограничение частоты. Тексты ошибок NVIDIA и секреты не выводятся. Ответ LLM отображается через textContent с постоянной пометкой «Синтетические данные», клиент защищён CSP.

Ошибки API: ожидаемые ошибки клиента возвращают 4xx с понятным текстом (400 — некорректный ввод, 404 — инцидент не найден, 409 — конфликт состояния, например повторный активный сценарий или завершённая смена; 403/413/415 — защита). Непредвиденная ошибка сервера возвращает 500 с общим текстом без внутренних деталей; в консоль сервера пишется только тип ошибки.

**Живой NVIDIA-вызов не проверен:** ключ для запуска не предоставлялся. Успешный ответ и ошибки проверены с тестовым mock. Локальное демо не имеет пользователей/авторизации и не предназначено для публикации в интернет. Host/CSRF не являются заменой production-аутентификации.

Официальная спецификация: [NVIDIA chat completions](https://docs.api.nvidia.com/nim/reference/meta-llama-3_3-70b-instruct-infer).

## Возможности и допущения модели

- Бейдж «Синтетические данные» закреплён в шапке и виден при прокрутке.
- 2D SVG-карта: сварка → окраска → сборка → контроль → отгрузка. Участок выбирается мышью, Tab+Enter/Space или кнопками под картой. Текущее узкое место отмечено на карте пунктирной рамкой и ярлыком «Узкое место». На экранах до 800 px схема прокручивается по горизонтали внутри своей области с читаемыми подписями; страница целиком не прокручивается вбок.
- Журнал инцидентов без обращения к AI показывает участок, причину-гипотезу, рекомендацию, действие устранения, время начала/окончания и статус.
- Смена 08:00–16:00, 480 плановых минут, план 400 годных автомобилей. Начало демо в 10:00 после детерминированного прогрева первых 120 минут; seed 42. Демо стартует на паузе, чтобы его удобно было презентовать.
- Старт/пауза, ручной шаг +5 минут, скорость 1/5/15 модельных минут за 1,2 реальной секунды, воспроизводимый сброс. В 16:00 симуляция останавливается.
- Линия упрощённо синхронная без буферов/WIP, отдельных маршрутов и материального баланса. Темп — минимум доступных мощностей участков. Один автомобиль считается в итоговом выпуске один раз. Все участки делят фактический поток и OEE; их отдельные мощности показываются как доступный темп.
- Базовое узкое место — сборка: 0,86 шт./мин. Базовая вероятность брака 2,5%. Дробный выпуск накапливается, целые изделия проверяются seeded-генератором.
- Остановка окраски: 45 минут нулевого потока всей линии. Рост брака: вероятность 22% на 60 минут, новые дефекты покрытия. Замедление сборки: 0,57 шт./мин на 60 минут. Можно сочетать разные сценарии; один тип нельзя включить повторно, пока он активен. Сценарии автоматически завершаются по длительности или вручную кнопкой «Устранить». Если расчётное восстановление позже 16:00, инцидент в конце смены получает статус «Не устранён к концу смены»: время окончания не придумывается, в журнале показывается фактическое расчётное время восстановления (например, 16:40).
- Мощности участков, вероятность брака и эффекты сценариев заданы в одном месте (`STATIONS`, `BASE_REJECT_RATE`, `SCENARIOS[*].effect` в `server/simulation.mjs`) и через `lineParameters()` используются симуляцией, прогнозом и локальным объяснением.
- Причины инцидентов — заданные гипотезы, а не автоматическая диагностика. Устранение влияет только на будущее, сохраняя историю.
- Состояние хранится в памяти одного серверного процесса; вкладки видят общую смену. Перезапуск сбрасывает её. Внешних шрифтов, CDN, аналитики и фоновых AI-вызовов нет.

### Метрики

План на минуту `t`: `400 × t / 480`. Факт — только годные, отклонение — `good − planNow`. `total = good + rejects`; сумма категорий брака равна `rejects`.

`Availability = runMinutes / elapsed`

`Performance = total × idealCycle / runMinutes`, где `idealCycle = 1 мин/шт.`

`Quality = good / total`

`OEE = Availability × Performance × Quality`

Нулевые знаменатели дают 0; округление только для отображения. Прогноз — `good + сумма(rate × yield)` по оставшимся минутам, с нулевым вкладом во время остановки и известным временем завершения активных сценариев. Новые инциденты не предполагаются. Будущие потери раскладываются по простою, темпу и качеству без двойного счёта. Диапазон — **±10% будущего выпуска**, не доверительный интервал и не обученная ML-модель. LLM объясняет рассчитанный снимок; после изменения состояния UI помечает объяснение устаревшим.

## API

| Endpoint | Назначение |
|---|---|
| `GET /api/health` | Статус сервера и факт наличия ключа, без значения ключа |
| `GET /api/state` | Авторитетный снимок смены и CSRF-токен |
| `POST /api/action` | JSON с `action`: play, pause, step, speed (value), scenario (type), resolve (id), reset |
| `POST /api/explain` | Пустой JSON `{}`, объяснение текущего серверного снимка |

Для POST нужны `Content-Type: application/json` и `X-CSRF-Token` из state. Неподдерживаемые файлы, включая `.env` и серверный код, не раздаются.

## Сборка

`npm.cmd run build` проверяет синтаксис сервера и клиента и собирает `dist` строго по белому списку: `index.html`, `app.js`, `styles.css`, `favicon.svg`. Посторонние файлы и папки, найденные в `dist`, не удаляются, а переносятся в `build-quarantine\<время сборки>\` с сообщением в консоли. Сборка также отказывается копировать клиентский файл, похожий на ключ NVIDIA. `.env` и серверный код в `dist` не попадают.
