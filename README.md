# Allur Smart Factory — производственная мастерская (этап 1)

Локальная синтетическая мастерская для демонстрации кейса №2: конкретные автомобили проходят маршрут через посты ограниченной вместимости, очереди и буферы; задания с приоритетом; неисправности отдельных постов; аналитика смены из того же состояния. **Все автомобили, задания, посты, нормативы, события, планировка и значения вымышлены. Это не действующий цифровой двойник Allur, не реальный CAD и не данные производства.** Структура следующей версии — в `WORKSHOP_SPEC.md`; реализован этап 1.

## Запуск на Windows / PowerShell

Нужен Node.js **22.13+** (проверено на 24.19.0) с npm. Сторонних зависимостей нет, `npm install` для запуска не нужен. Node должен быть в PATH. Используем `npm.cmd`, чтобы не менять ExecutionPolicy PowerShell.

```powershell
Set-Location 'C:\Users\ADMIN\Documents\Codex\2026-10-08\referenced-chatgpt-conversation-this-is-an-2\outputs\allur-smart-factory'
node --version
npm.cmd test
if ($LASTEXITCODE -ne 0) { throw 'Тесты не прошли' }
npm.cmd run build
if ($LASTEXITCODE -ne 0) { throw 'Сборка не прошла' }
npm.cmd start
```

В другом окне PowerShell:

```powershell
Start-Process 'http://127.0.0.1:3000'
```

Остановка сервера: **Ctrl+C**. Если порт занят уже запущенным демо, используйте его. Для второго экземпляра:

```powershell
$env:PORT = '3001'
npm.cmd start
# Открыть http://127.0.0.1:3001
```

Сервер доступен только на этом компьютере. `dist` — только клиент; его нельзя запускать двойным кликом или как самостоятельный статический сайт: UI нужен локальный API. После изменения файлов `public` повторите `npm.cmd run build` и обновите страницу. После изменения сервера перезапустите `npm.cmd start`; `npm.cmd run dev` перезапускает сервер автоматически и сбрасывает состояние.

## OpenAI API — подключение ключа

В PowerShell из папки проекта выполните `npm.cmd run start:openai`. В приглашении `OpenAI API key` вставьте ключ и нажмите Enter: ввод скрыт, ключ не записывается в файл или историю команд. Скрипт запускает отдельную смену на **http://127.0.0.1:3001/#shift**, чтобы не мешать демо на 3000. Нажмите «Объяснить»: успешный ответ отмечается **OpenAI**, fallback — «Локальное объяснение» с причиной. Остановка — Ctrl+C; переменные окружения скрипта восстанавливаются. Для другого порта: `npm.cmd run start:openai -- -Port 3002`. Скрипт не останавливает чужие процессы и не меняет ExecutionPolicy.

Модель по умолчанию — `gpt-4.1-mini`. Сервер отправляет только синтетический снимок в `https://api.openai.com/v1/responses`, с `store: false` и лимитом 900 выходных токенов. Ключ передаётся только в серверном заголовке Authorization. Ответ не изменяет симуляцию и численный прогноз. URL API фиксирован, перенаправления запрещены. Проверка `/api/health` сообщает только выбранного провайдера и наличие ключа; наличие ключа не подтверждает его действительность.

Альтернативный запуск через `.env`: скопируйте `.env.example` только если `.env` ещё не существует. Установите `AI_PROVIDER=openai`, заполните `OPENAI_API_KEY` в локальном редакторе, при необходимости измените `OPENAI_MODEL`, затем перезапустите `npm.cmd start`. `.env` исключён из Git, сборки и HTTP-раздачи. Ключ не присылайте в чат и не вставляйте в браузер.

Выбор провайдера: `AI_PROVIDER=openai`, `nvidia` или `local`. Без явного выбора используется OpenAI при наличии его ключа, иначе NVIDIA при наличии её ключа, иначе локальное объяснение с сообщением об отсутствии ключа OpenAI. При ошибке выбранного провайдера выполняется только локальный fallback; запросы не пересылаются другому провайдеру.

Официальная документация: [Responses API](https://developers.openai.com/api/reference/typescript/resources/responses/methods/create), [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini). Реальный OpenAI-вызов пока не проверен: нужен ключ пользователя. Автотесты используют имитацию ответов API без платных запросов.

## NVIDIA AI API и общая защита

Полное демо работает **без ключа и без интернета**. Кнопка «Объяснить» в разделе «Смена и аналитика» вернёт локальный разбор с явной причиной fallback.

Для реального NVIDIA-вызова остановите сервер и в его PowerShell-окне введите ключ без отображения на экране и без помещения самого ключа в историю команд:

```powershell
$allurKey = Read-Host 'NVIDIA API key' -AsSecureString
$env:NVIDIA_API_KEY = [System.Net.NetworkCredential]::new('', $allurKey).Password
$env:NVIDIA_MODEL = 'meta/llama-3.3-70b-instruct'
$env:AI_PROVIDER = 'nvidia'
try {
    npm.cmd start
}
finally {
    Remove-Item Env:NVIDIA_API_KEY -ErrorAction SilentlyContinue
    $allurKey = $null
}
```

Альтернатива — локальный `.env`: скопируйте `.env.example` только если `.env` ещё нет, откройте его редактором, установите `AI_PROVIDER=nvidia` и заполните `NVIDIA_API_KEY`. Он исключён из Git и сборки. Не вводите ключ в браузер или чат и не включайте `.env` в архив для передачи. Для принудительного offline-демо установите `AI_PROVIDER=local`.

Вызов: браузер → `POST /api/explain` → Node.js → `https://integrate.api.nvidia.com/v1/chat/completions`. Используется модель `meta/llama-3.3-70b-instruct` (можно изменить `NVIDIA_MODEL`). Передаётся только синтетический снимок. Результат — текстовое объяснение, которое не управляет оборудованием и не меняет численный прогноз.

Защита: сервер слушает 127.0.0.1, проверяет Host/Origin/Sec-Fetch-Site и CSRF для POST, ограничивает запрос 4 КБ, принимает только известные действия, не принимает ключ/endpoint/prompt от клиента. Обычный переход по ссылке с другого сайта открывает только саму страницу `/` (`Sec-Fetch-Mode: navigate`, `Sec-Fetch-Dest: document`); API и статические файлы для чужих сайтов закрыты, проверка Host действует всегда, встраивание во фрейм запрещено.

AI: при настроенном ключе — один запрос к выбранному провайдеру за 10 секунд и один одновременно, таймаут 20 секунд для OpenAI и 8 секунд для NVIDIA, максимум 64 КБ ответа. Без ключа сеть не используется, поэтому локальное объяснение выдаётся при каждом нажатии без ограничения частоты. Причины fallback различаются и видны в интерфейсе: ключ не настроен, ключ отклонён (401/403), лимит API (429), ошибка сервера (5xx), другой HTTP-статус, сеть, таймаут, некорректный ответ, локальное ограничение частоты. Тексты ошибок провайдера и секреты не выводятся. Ответ LLM отображается через textContent с постоянной пометкой «Синтетические данные», клиент защищён CSP.

Ошибки API: ожидаемые ошибки клиента возвращают 4xx с понятным текстом (400 — некорректный ввод, 404 — пост, задание, автомобиль или инцидент не найден, 409 — конфликт состояния, например второй инцидент на посту, занятый целевой пост, лимит автомобилей или завершённая смена; 403/413/415 — защита). Непредвиденная ошибка сервера возвращает 500 с общим текстом без внутренних деталей; в консоль сервера пишется только тип ошибки.

**Живой NVIDIA-вызов не проверен:** ключ для запуска не предоставлялся. Успешный ответ и ошибки проверены с тестовым mock. Локальное демо не имеет пользователей/авторизации и не предназначено для публикации в интернет. Host/CSRF не являются заменой production-аутентификации.

Официальная спецификация: [NVIDIA chat completions](https://docs.api.nvidia.com/nim/reference/meta-llama-3_3-70b-instruct-infer).

## Разделы интерфейса (этап 1)

- **Цех** — условная 2D-карта: входной буфер кузовов → сварка (СВ-1, СВ-2) → буфер B1 → окраска (ОК-1, ОК-2) → B2 → сборка (СБ-1…СБ-3) → B3 → контроль (КК-1, КК-2) → готовые автомобили → отгрузка (ОТ-1). На постах видны автомобиль, операция, прогресс и текстовый статус; в буферах — конкретные автомобили и заполненность. Выбор поста (мышью, Tab+Enter/Space или из списка «Посты по участкам») открывает карточку: автомобиль, операция, прогресс, норматив/факт, причина задержки, очередь участка и действия — неисправность, снижение темпа, устранение, перевод автомобиля на свободный параллельный пост.
- **Автомобили** — список с фильтрами и паспорт: синтетический ID `DEMO-xxx` (не VIN), модель A/B/C, задание, приоритет, маршрут из 5 операций с постами и временем, текущая операция и история событий.
- **Производственные задания** — выпуск задания (модель, количество 1–8, приоритет), смена приоритета, выполнение по связанным автомобилям: не начаты / в работе / приняты / отгружены, срок.
- **Смена и аналитика** — график приёмки «план / факт / прогноз», баланс автомобилей, WIP, среднее время прохождения, A/P/Q/OEE по каждому посту с разбивкой простоев, сценарный прогноз с ограничивающим участком, журнал инцидентов, журнал событий, локальное, OpenAI- или NVIDIA-объяснение.

Общие для всех разделов: закреплённый бейдж «Синтетические данные», часы смены, запуск/пауза, шаг +5 минут, скорость 1/5/15 модельных минут за 1,2 с, воспроизводимый сброс.

## Модель мастерской

- Смена 08:00–16:00 (480 мин), seed 42. Начальные синтетические задания выпущены в 08:00: ORD-101 модель A × 6, ORD-102 B × 8 (обычный приоритет), ORD-103 C × 6 (низкий) — 20 автомобилей. Демо открывается в 11:00 на паузе после детерминированного прогрева.
- 10 постов вместимостью 1; параллельные посты работают независимо. Буферы ограничены: B1 = 3, B2 = 3, B3 = 2, готовые = 4; входной буфер — очередь выпущенных заданий. Если следующий буфер заполнен, автомобиль остаётся на посту, пост «блокирован следующим буфером» — так задержка распространяется назад.
- Нормативы (мин, синтетика): сварка A/B/C 28/30/33, окраска 30/33/35, сборка 50/56/62, контроль 22/24/26, отгрузка 8. Фактическая длительность каждого автомобиля отличается на −5…+10% и задаётся seed при выпуске задания. Узкое место без сбоев — сборка.
- Очередь участка: приоритет задания → время прихода в буфер → порядок создания. Смена приоритета меняет только ещё не начатые операции; начатые не прерываются.
- Неисправность поста — 60 мин (пост стоит, операция на паузе, автомобиль остаётся на посту), снижение темпа — 60 мин при 60% скорости. Один активный инцидент на пост. Восстановление по расчёту или кнопкой «Устранить». Автомобиль с неисправного поста можно перевести на свободный исправный пост того же участка — остаток операции сохраняется.
- Годный выпуск = автомобили, завершившие контроль (этап 1: контроль без дефектов, доработка — этап 2). Каждый считается один раз; отгрузка уже принятых выпуск не увеличивает. Баланс: создано = не начаты + в работе + готовы к отгрузке + отгружены.
- В 16:00 смена останавливается: автомобили остаются на местах, операции — незавершёнными, активные инциденты получают статус «Не устранён к концу смены» с расчётным временем восстановления. Ничего не превращается в завершённое само.
- Склад, работники, материалы, доработка и сохранение состояния на диск — этап 2 по `WORKSHOP_SPEC.md`; в этапе 1 они не моделируются и на карте не изображаются.

### План, прогноз и метрики

**План смены** — эталонный прогон того же движка: тот же seed и начальные задания, без инцидентов, до 16:00. Для seed 42 это 18 принятых автомобилей из 20 (2 остаются в работе — ограничение мощности сборки). План к текущей минуте — накопленная приёмка эталонного прогона, поэтому до первых приёмок (после 10:00) он равен 0. Прежний счётчик 400 машин синхронной линии удалён из работы и сохранён в `archive/v1`.

**Прогноз** — копия текущего состояния прогоняется тем же движком до 16:00 с известными очередями, приоритетами и сроками восстановления; исходное состояние и генератор не меняются. Сценарный диапазон: нижняя граница — если активные инциденты не устранят до конца смены. Это не статистический интервал и не ML-модель. Ограничивающий участок — с наибольшей загрузкой постов в оставшееся время.

**OEE по посту**, плановое время = прошедшие минуты смены: `A = работа / плановое время` (все остановки поста — неисправность, нет автомобиля на входе, блокировка — потери доступности, показаны раздельно); `P = нормативная работа / минуты работы`; `Q = 100%` на этапе 1; `OEE = A × P × Q`. Среднего «OEE завода» нет, выпуск показывается отдельно. Нулевое время даёт 0.

## API

| Endpoint | Назначение |
|---|---|
| `GET /api/health` | Статус сервера и факт наличия ключа, без значения ключа |
| `GET /api/state` | Авторитетный снимок мастерской (одна revision для всех разделов) и CSRF-токен |
| `POST /api/action` | JSON с `action`: `play`, `pause`, `step`, `speed` (`value` 1/5/15), `release` (`model` A/B/C, `quantity` 1–8, `priority` high/normal/low), `priority` (`orderId`, `priority`), `fault` (`postId`, `kind` breakdown/slowdown), `resolve` (`id`), `transfer` (`vehicleId`, `postId`), `reset` |
| `POST /api/explain` | Пустой JSON `{}`, объяснение текущего серверного снимка |

Для POST нужны `Content-Type: application/json` и `X-CSRF-Token` из state. Предусловия команд проверяет сервер: лимит 24 автомобиля на смену, один инцидент на пост, перевод только с неисправного поста на свободный исправный пост того же участка, после 16:00 команды изменения смены отклоняются (409). Неподдерживаемые файлы, включая `.env` и серверный код, не раздаются.

## Сборка

`npm.cmd run build` проверяет синтаксис сервера и клиента и собирает `dist` строго по белому списку: `index.html`, `app.js`, `styles.css`, `favicon.svg`. Посторонние файлы и папки, найденные в `dist`, не удаляются, а переносятся в `build-quarantine\<время сборки>\` с сообщением в консоли. Сборка также отказывается копировать клиентский файл, похожий на ключ NVIDIA. `.env` и серверный код в `dist` не попадают.
