## Проверка нижних карточек: длинные тексты и низкая высота

Подтверждены дефекты на прежней версии 92b55f7:
- На 320×568 футер PR-1 заканчивался на y=656.6 и обрезался карточкой на y=568 без прокрутки к нему.
- На 390×844 футер чата заканчивался на y=885.2, кнопка отправки обрезалась.
- На 640×320 футер чата заканчивался на y=555.6; фиксированные шапка и футер оставляли телу лишь 28 px.
- Заголовок PR-1 со списком автомобилей расширял содержимое до 421 px при клиентской ширине 318/388/412 px.

Мобильная карточка теперь прокручивается целиком: заголовок, тело и футер находятся в одном потоке. Длинные статусы, список автомобилей и подписи измерений переносятся. Правила ограничены шириной до 1100 px; логика диалогов и analytics не менялась. Чтобы вернуться к закрытию после чтения длинной карточки, нужно прокрутить к началу (или нажать Escape).

Regression: `scripts/check-mobile-cards.mjs`. После build и запуска локального сервера :3029 задайте `PLAYWRIGHT_MODULE` как file URL установленного Playwright и выполните `node scripts/check-mobile-cards.mjs`. Новых npm-зависимостей нет. Данные формируются Workshop локально, GET state подменён fixture, все POST блокируются. Скрипт проверяет геометрию и доступность клика через elementFromPoint после scrollIntoViewIfNeeded, длинный заголовок, переход из PR-1 в чат, поле ввода, кнопку отправки и закрытие.

Пройдено: 320×568, 390×844, 414×736, 844×390, 640×320 и desktop 1440×900; npm.cmd test 86/86; npm.cmd run build. На desktop сохраняется flex-раскладка боковой панели; существующее переполнение списка автомобилей на 3 px находится вне мобильных правил этого прохода.
