# Как работать над Allur Smart Factory командой

Цель — чтобы каждый делал свою задачу и не мешал другим. Общая ветка `main` всегда рабочая: в неё попадает только проверенное через pull request.

## 1. Порядок работы

1. Возьмите задачу (GitHub Issues или доска Projects) и назначьте её на себя, чтобы двое не делали одно и то же.
2. Обновите `main` и создайте свою ветку:
   ```bash
   git switch main
   git pull
   git switch -c feature/короткое-название
   ```
   Префиксы: `feature/` — новое, `fix/` — исправление, `docs/` — документация.
3. Работайте небольшими коммитами. Раз в день подтягивайте `main`, чтобы конфликты оставались мелкими:
   ```bash
   git fetch origin
   git merge origin/main
   ```
4. Перед отправкой проверьте локально (на Windows — `npm.cmd`):
   ```bash
   npm test
   npm run build
   ```
5. Отправьте ветку и откройте pull request в `main`:
   ```bash
   git push -u origin feature/короткое-название
   ```
   GitHub сам запустит тесты и сборку (`.github/workflows/ci.yml`) и позовёт ответственного за зону (`.github/CODEOWNERS`).
6. После зелёной проверки и одобрения — слияние. Ветку после слияния можно удалить.

Напрямую в `main` не пушим. Задача — на 1–2 дня; большую работу делим на несколько pull request.

## 2. Зоны проекта

| Зона | Файлы |
|---|---|
| Производственный движок | `server/simulation.mjs`, `server/equipment.mjs`, `server/decisions.mjs`, `server/components.mjs` (узлы машины и синтетические проверки), `server/workflow.mjs` (ремонт по дефекту, следующее действие, задачи) |
| Сервер и безопасность | `server/index.mjs`, `server/store.mjs` |
| AI и чат | `server/ai.mjs`, `server/ai-config.mjs`, `server/chat.mjs` |
| Изометрическая сцена | `public/scene.js` (цех «Сборка»), `public/shops/*.js` (сцены остальных цехов, после платформы `public/shop-scene.js`) |
| 3D-карточка автомобиля | `public/viewer3d.js` (Three.js, кузов Kia Sportage из `assets-src/`, условные узлы), `public/app/65-car3d.js` (панель); картинки машин для сцены — `public/car-kia-*.webp` (`npm run sprites`); библиотеки `public/three.module.js`, `public/three-orbit-controls.js` не правим — см. `docs/ASSETS.md` |
| Интерфейс | `public/app/*.js`, `public/index.html`, `public/styles.css` |
| ML и сравнение стратегий | `scripts/train-lift-risk.mjs`, `scripts/compare-policies.mjs`, `models/`, `reports/` |
| Тесты | `tests/` |

Если задача требует правок в чужой зоне — предупредите ответственного в задаче или в pull request.

### Кто чем занимается

|---|---|---|
| **Абзал** (`ab0ka`) | `движок`, `ml`, `политики`, `документация`, `инфраструктура`; проверка pull request | `engine/…`, `ml/…`, `docs/…` |

Задачи — в [Issues](https://github.com/ab0ka/ALLUR-SMART-FACTORY/issues): фильтр по метке с именем показывает свои задачи. Одна задача — одна ветка — один pull request; в описании pull request пишите `Closes #номер`, тогда задача закроется при слиянии.

Диас и Тони чаще всего пересекаются в `public/app/50-spaces.js` и `public/scene.js` (карта предприятия): о правках там договаривайтесь в задаче заранее.

**Сцена и `public/app/*`.** Задачи сцены (метки `сцена-сборка`, `сцены-цехов`) делаются внутри `public/scene.js` и `public/shops/*`; `public/app/*` в них не правим, даже если файл указан в задаче. Сцена получает всё нужное через `update(state, ui)`: выбранный объект — `ui.selected`, открытая карточка — `ui.panel`. Если без правки в `public/app/*` не обойтись — напишите Абзалу в задаче, он сделает подключение отдельным коммитом.

### Клиентский скрипт разбит на части

`public/app/` содержит части одного скрипта; сборка склеивает их по порядку имён в `dist/app.js`:

| Файл | Что внутри |
|---|---|
| `00-core.js` | импорт сцены, общие помощники, запросы к API, подтверждения, верхняя панель |
| `10-dispatcher-chat.js` | «Задачи и решения»: список задач от сервера, журнал решений, отправка вопросов в чат |
| `20-workshop-map.js` | 2D-схема цеха, карточка и доска постов |
| `30-vehicles-orders.js` | автомобили и задания |
| `40-shift-lab.js` | смена и аналитика, лаборатория моделей |
| `50-spaces.js` | пространства: сцена, карта предприятия, общий вид цеха (вход → посты → задачи → выход), таблица |
| `55-vehicle-card.js` | единая карточка автомобиля, операции с машиной, навигация с возвратом |
| `60-ribbon-side-panels.js` | лента событий и боковые карточки (пост, проблема, сравнение, чат) |
| `65-car3d.js` | 3D-осмотр: Kia, капот, узлы под капотом; операции — через общую карточку |
| `70-space-navigation.js` | выбор объектов, переходы, камера, клавиатура |
| `90-routing-startup.js` | маршрутизация, обработчики событий, запуск |

Все части работают в одной области видимости, поэтому функции из одной части доступны в другой. Новую часть называйте `NN-имя.js` (две цифры и латиница) — номер задаёт место в итоговом файле. После правок всегда запускайте `npm run build`: сервер отдаёт файлы из `dist/`.

## 3. Локальный запуск — у каждого свой

Чтобы не затирать чужие данные и не занимать чужой порт, задайте свой порт и свой файл смены:

```powershell
$env:PORT='3031'; $env:AI_PROVIDER='local'; $env:ALLUR_STATE_FILE='ivan.json'; node server/index.mjs
```

- Порты 3000 и 3001 оставьте для общего демо. Чужие процессы не останавливайте.
- Состояние смены пишется в `data/` — папка не попадает в Git.
- Ключ OpenAI/NVIDIA — только в своём `.env`. Его никогда не коммитят и не вставляют в код, чат, скриншоты.

## 4. Правила проекта

- Все производственные данные синтетические (`DEMO-xxx`, условные посты и нормативы). Не выдавать их за данные Allur.
- Интерфейс рисует только то, что есть в снимке сервера. Клиентской симуляции нет; анимация лишь проводит машину между двумя снимками.
- Изменения производства (проверки, ремонт, перевод, решения, снятие поста с загрузки) — только через подтверждение.
- Inline-стили запрещены политикой CSP: используйте классы в `public/styles.css` и SVG-атрибуты.
- Не переписывайте движок ради визуализации; новые возможности движка — с тестами.
- Защиту сервера (Host/Origin/CSRF/CSP, лимиты тела запроса) не ослаблять.
