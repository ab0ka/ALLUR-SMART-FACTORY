## 4. Незавершённые этапы прежнего задания

Задание «Диспетчер смены» — порядок A → E.

**D. ML — НЕ СДЕЛАНО.** Нужен `scripts/train-lift-risk.mjs` (Node, без зависимостей) и `npm` скрипт `train`.
- **Задача:** риск отказа подъёмника в ближайшие 30 модельных минут.
- **Данные:** ~300 синтетических смен через реальный `Workshop`. Параметр `episode: {postId, cause, onset, duration}` или `false`: ~70% смен с эпизодом — onset 60–400, duration 90–260; остальные без. Все 3 подъёмника каждой смены.
- **Признаки:** `features()` из `equipment.mjs`, `FEATURES`; только данные до момента t.
- **Метка:** отказ в (t, t+30]. Окна после отказа исключить; цензурированные концы (t+30 > 480 без отказа) исключить.
- **Разбиение:** по целым сменам 60/20/20; стандартизация только по train.
- **Baseline:** порог `cycle_mean`, подобранный на validation.
- **Модель:** логистическая регрессия (L2, градиентный спуск, фиксированный seed), порог по F1 на validation.
- **Метрики на test:** precision, recall, F1, PR-AUC, ложные тревоги на смену, время предупреждения (медиана, успели/всего), калибровка по бинам + Brier.
- **Артефакт** `models/lift-risk-v1.json` должен иметь поля, которые ждёт `risk-model.mjs`: `format: 'allur-lift-risk'`, `generatorVersion` = `LIFT_MODEL_VERSION`, `features`, `mean`, `std`, `weights`, `bias`, `threshold`, `baseline {feature, threshold}`, `selected` (`'model'` или `'baseline'` — что лучше по test PR-AUC), `selectionReason`, `modelVersion`, `modelType`, `task`, `horizon`, `featureWindow`, `trainingSeed`, `data {shifts{total,train,validation,test}, samples{total,train,validation,test}, positiveRate}`, `metrics {test{model,baseline}, validation{model,baseline}}` — у каждой метрики `precision`, `recall`, `f1`, `prAuc`, `falseAlarmsPerShift`, `leadTime{median,warned,failures}`, `brier`; `calibration [{from,to,count,meanPredicted,observedRate}]`, `limitations[]`. UI лаборатории уже рендерит эти поля.
- **Тесты без утечки:** признаки не зависят от будущих замеров; смены в train и test не пересекаются; стандартизация только по train; воспроизводимость.

Чат понимает выбранный объект; ссылки ведут к автомобилю, посту, событию или сравнению. Изменения производства — с понятным подтверждением; просмотр, переключение цехов и камера — без подтверждений.
>
> УДОБСТВО И ПРОИЗВОДИТЕЛЬНОСТЬ — на ноутбуке одновременно читаются сцена, навигация и карточка объекта; на мобильном карточка снизу; подписи не мельчить. Статусы текстом и значком, не только цветом. Клавиатура и табличное представление объектов. Не запускать отдельный цикл анимации на каждый автомобиль; освобождать ресурсы при смене сцены; запасной режим при недоступности объёмной графики.
>
> ПРОВЕРКА И ПЕРЕДАЧА — сначала один завершённый маршрут взаимодействия в одном цехе, затем остальные пространства. Проверить: соответствие объектов серверному состоянию; выбор автомобиля и переходы по ссылкам; паузу, ускорение, переключение цехов; неисправность, диагностику, ремонт и повторную проверку; отсутствие двойных действий; чат; desktop/mobile; сборку и тесты. Скриншоты общего вида, выбранного автомобиля и диагностики, адрес демо, ограничения. Не выводить ключи, не менять .env, не пушить в GitHub, свой свободный порт. Критерий: пользователь видит живое производство, понимает состояние конкретной машины и может провести её через диагностику и исправление в одном визуальном пространстве.

Затем пользователь уточнил: **«сделай просто в клауд дизайн и утвердим дизайн»** — то есть сначала макет в Claude Design на утверждение, без изменения кода.

### Как пространства соотносятся с движком (для честного макета)

| Пространство | Сущности движка | Что можно показать |
|---|---|---|
| Предприятие | Общая карта всех участков | Всё |
| Сборка | Посты A1–A3 (СБ-1..3) с гидроподъёмниками, буфер B2 | Самый «живой» цех — с него начинать |
| Испытания | Контроль Q1–Q2 (КК-1..2), буфер B3, результаты контроля | Есть |
| Диагностика | Не отдельный цех, а проверки техника на подъёмниках: проблемы PR-x, работы JOB-x, техник T1, склад | Показывать как режим или слой сборки, а не как отдельный цех с машинами |
| Доработка | Пост R1 (ДР-1), очередь RWQ | Есть |
| Отгрузка | S1 (ОТ-1), буфер FG, отгруженные | Есть |
| Сварка, окраска | W1–W2, P1–P2, буфер B1 | Остаются в маршруте и на общей карте; доступ из «Предприятия» |

Испытательных стендов как отдельного оборудования в движке нет — есть пост контроля. Не изображать несуществующее работающим.
