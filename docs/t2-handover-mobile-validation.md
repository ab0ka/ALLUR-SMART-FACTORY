# Мобильная проверка центра передачи смены

Проверена интеграция `eae50107d0ff6bbced9040e65d3f43e936d13a95` из PR62, 8 октября 2026 года. Приёмка 414 px не пройдена: навигация расширяет страницу до 420 px. Проверка выполнена в отдельной копии; исходники T9/T10 не изменялись.

## Зависимости и область проверки

- T8 API и T7: `ce81a2665667e28201bc8c3f6f76da528767883c`, PR59.
- T9 экран: `f9fb5290e51e121223396b4bd4430e92ec4ec82b`, PR60.
- T10 списки: `5891ebeb67cf2494f7c0c21ba585fd66ab6cf49c`, PR58.
- Мобильные изменения T2 из PR55 и необязательная карточка заказа T1 `ba829c81` в этот прогон не включены. Результаты относятся только к указанному SHA, до последующих исправлений провайдеров.

## Подтверждённые дефекты

1. `#analytics-navigation > a[data-nav="lab"]`: при 414 px x=259, width=160,78125, right=419,78125, height=32; clientWidth и scrollWidth равны 161. Правило `.context-tabs a { white-space:nowrap }` вместе с автоматическим min-width мешает сжатию. Минимальное предложение T9 для max-width:760px: `#analytics-navigation > a { min-width:0; white-space:normal; min-height:40px }`. Исправление здесь не применялось и не проверялось.
2. `loadHandover()` в `public/app/45-handover.js` восстанавливает фокус до снятия disabled с `#handover-refresh`. Enter и задержанный на 200 ms ответ success/503/retry оставляют activeElement на BODY. Восстановление нужно выполнять после включения кнопки с сохранением защиты от перехвата фокуса.
3. `.handover-items-link` остаётся inline-ссылкой высотой 20 px. Самостоятельная ссылка ORD-101 имеет размер 64,1875×20 px и не достигает требуемых 40×40.

## Артефакты и воспроизведение

- `screenshots/t2-handover/summary.json` — компактная геометрия и результаты.
- `screenshots/t2-handover/results.json` — полные измерения.
- PNG baseline, error, disclosure и long-top для каждого из трёх размеров сохранены рядом. Визуально проверены error-414, long-top-896, disclosure-414 и disclosure-640.
- `scripts/check-handover-mobile.mjs` — сбор и сохранение доказательств. Код завершения 0 означает успешное выполнение сценария, а не отсутствие дефектов; результаты нужно оценивать по измерениям.

Запуск из корня отдельного checkout требует Node, Playwright и установленного Edge. Если Playwright находится вне node_modules, задайте PLAYWRIGHT_MODULE как file URL к его index.mjs. Затем выполните `node scripts/check-handover-mobile.mjs`.

Сценарий использует свободный порт 3029, создаёт свежий Workshop, не читает .env или сохранённое состояние и блокирует браузерные запросы с изменением данных. Искусственные длинные строки и 503 подаются только через перехват браузерного GET. Сервер и браузер закрываются в finally; после зафиксированного прогона порт 3029 освобождён. Экспорт файлов, точность всех метрик, 1280/390 и карточка заказа не входили в дополнительный мобильный прогон. Восстановление раскрытия и исходного элемента после Back из шестой строки отдельно не проверялось.

После прогона сценарий подготовлен к публикации: путь Playwright вынесен в переменную окружения, а записываемый SHA читается из Git. Проверен синтаксис; браузер повторно не запускался. Сохранённые результаты относятся к исходному eae5010.
