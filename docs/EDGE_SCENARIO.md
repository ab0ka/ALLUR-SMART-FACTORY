# T6 — основной сценарий в Microsoft Edge

Команда `npm.cmd run test:edge` запускает установленный Microsoft Edge через уже доступный Playwright. Новых npm-зависимостей нет. Нужны Node >=22.13, Microsoft Edge и существующий модуль Playwright.

```powershell
npm.cmd run build
$env:PLAYWRIGHT_MODULE='C:/path/to/existing/playwright/index.mjs'
$env:EDGE_PORT='3033'
npm.cmd run test:edge
```

Замените пример пути абсолютным путём к своему существующему Playwright `index.mjs`. Скрипт ничего не устанавливает и при отсутствии Edge/модуля завершается с ошибкой. Обычный `npm.cmd test` остаётся независимым от браузера; существующий Linux CI не выдаётся за проверку Edge.

Каждый запуск поднимает настоящий `createApp` с новой синтетической `Workshop`, локальным AI и уникальной папкой `data/edge-<random>/`. `.env` не загружается. Сервер слушает только 127.0.0.1; занятый порт вызывает ошибку, подключения к чужой сессии нет. В конце закрываются только созданные этим скриптом браузер и сервер. Сохранённое состояние, семь PNG и `report.json` остаются в папке запуска. При ошибке сохраняется `failure.png`, процесс возвращает ненулевой код.

Все изменения производства и продвижение времени выполняются кликами: меню «Разделы» → шаг +5 минут, автомобиль на сцене → диагностика → проверка → сравнение → ремонт. GET `/api/state` используется только для утверждений. Нет подмены API, прямого advance, вызова клиентских обработчиков или доступа к скрытой причине.

Проверяется естественное обнаружение отклонения, выбор автомобиля, отмена и принятие обоих подтверждений, результат проверки, отсутствие автоматического ремонта после отдельной диагностики, одно решение, резервирование и однократный расход запчасти, автоматическая проверка восстановления, освобождение техника, закрытие проблемы и отображение закрытого состояния после перезагрузки. Ошибки JS, консоли (включая CSP) и HTTP >=400 проваливают прогон. Время ожидается через ответы API/локаторы, без фиксированных пауз.

## Проверка отказов

Папка артефактов выделяется атомарно через mkdtemp и не переиспользуется даже при одинаковом времени запуска. Для отдельной временной директории можно задать EDGE_ARTIFACT_DIR; внутри неё всегда создаётся новая подпапка. Отсутствующий модуль Playwright и невозможность запуска Edge дают пояснение без автоматической установки.

Регрессионный тест tests/edge-runner.test.mjs воспроизводит ранний отказ ожидания ответа при ещё выполняющемся клике, отсутствие Edge/Playwright и совпадающее время запусков. Подменяется только браузерный адаптер в дочернем процессе; сервер настоящий. Проверяются ненулевой код, сохранение failure.png, вызов закрытия собственного браузера, освобождение порта 3033 и сохранность старых артефактов. Эти проверки входят в npm.cmd test; они не заменяют реальный прогон Edge.

После исправления отказов: npm.cmd test — 87/87, сборка и полный Edge-сценарий — PASS. Дополнительно в настоящем Edge воспроизведён искусственный отказ ответа при незавершённом клике: failure.png сохранён, браузер отключён и закрыт, слушатель порта 3033 отсутствует. Недоступность Edge проверяется инъекцией ошибки запуска, без удаления установленного браузера.
