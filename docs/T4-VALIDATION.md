## Проверка границ показателей — дополнительный проход

Подтверждённая проблема: при elapsed=0 и нулевых run/completed UI показывал условные значения движка A/P/OEE=0%, Q=100% как измеренные показатели. Теперь только в таблице интерфейса неопределённый показатель обозначается «—» с пояснением: A требует прошедшего времени, P — времени работы, Q производственных участков — завершённой операции; Q контроля/доработки/отгрузки задано моделью как 100%, OEE — определённости всех трёх компонентов. При ненулевом знаменателе показывается исходное значение снимка; настоящий 0% сохраняется. Движок не менялся.

Регрессии tests/shift-ui.test.mjs используют renderShift и реальные снимки Workshop: начало/конец смены; независимые план, эталон, прогноз и факт; отсутствие эталона; нулевые знаменатели и настоящий нулевой результат. Нулевой план недопустим по серверному контракту (1–24); проверено отклонение setPlanTarget(0). Forecast в текущем snapshot обязателен: отсутствие не является поддерживаемым состоянием, общего fallback интерфейса для повреждённого снимка этот PR не добавляет. На границах forecast присутствует, в конце projected равен actual.

Проверки после исправления: npm.cmd test — 89/89, npm.cmd run build — OK. Edge 1440×1000 и 390×844: снимки 08:00 и 16:00 от реального движка подставлены только в GET /api/state через Playwright route; работающая смена не изменялась. Сверены четыре карточки и все 11 строк OEE, нет переполнения страницы или JS/CSP-ошибок.
