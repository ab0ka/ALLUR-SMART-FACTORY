# Проверка центра передачи смены

Все данные сценария синтетические. Исходная база T11: PR45,
`6d03fbf29350a6be23379f81563c28b525ecbccb`. Финальный Edge E2E выполнен на
`2e095acf43629dc1fa31f8967a9ec2ea52c4a529`: PASS, exit 0.

## Запуск

```powershell
$env:AI_PROVIDER='local'
$env:HANDOVER_PORT='3054'
node --test tests/e2e-handover.test.mjs
node scripts/e2e-handover.mjs
```

Установленный Edge и нативный CDP/WebSocket Node 24; без npm-зависимостей.
`HANDOVER_BROWSER` — абсолютный путь к Edge. Отсутствующий браузер даёт явный
SKIP, который не означает успешную E2E-проверку. Остальные ошибки дают exit 1.
Занятый порт не переиспользуется, чужие серверы не останавливаются.

Сценарий собирает dist и запускает createApp с отдельным Workshop и local AI.
Он не читает `.env` и существующие сохранения. Уникальный state-файл и профиль
браузера находятся в созданном для запуска временном каталоге. Cleanup в finally
закрывает собственный сервер/браузер и удаляет только этот каталог.
HTTP/CDP ограничены таймаутами. Основной сценарий имеет предел 180 секунд;
cleanup — отдельный жёсткий предел 120 секунд. Это не общий лимит 180 секунд.
При превышении cleanup watchdog завершает только runner с exit 1 и сообщает
путь возможного оставшегося профиля; успешный PASS не печатается.

## Проверяемый маршрут

1. Свежий Workshop: неисправность A1, ремонт, продвижение на 15 минут.
2. `/api/handover`: схема, числа относительно одного snapshot, нули,
   open/unresolved проблемы, queued/running работы, текущие задачи/заказы,
   техники и склад, последние 20 событий seq/type, отсутствие приватных полей.
3. Повторный GET детерминирован и не меняет производство. JSON/CSV: тип, UTF-8,
   attachment и содержимое; некорректный format даёт 400.
4. `#handover` при 1280, 390 и 414 px: сущности/ресурсы, метрики,
   отсутствие горизонтального overflow, снимки экрана.
5. Enter в реальную карточку проблемы и browser Back; карточка заказа и Escape.
   Возврат фокуса строго на исходный `data-focus-key`, видимый Tab-фокус.
6. CDP задерживает GET отчёта: loading, искусственный 503, ошибка,
   клавиатурный retry и восстановление содержимого.
7. Нет неожиданных console/page ошибок; просмотр не меняет snapshot.

Артефакты: отдельная ignored `screenshots/handover/run-*/` на каждый запуск —
PNG, JSON, CSV и geometry JSON. Метрики сверяются по девяти фактическим
`data-handover-metric`, включая процентное представление FPY. Искусственный
сетевой 503 допускается только на этапе ошибки. Layout/scroll width сравниваются
с заданной шириной устройства: сравнения только с innerWidth недостаточно,
потому что мобильный браузер может сам расширить layout viewport.

## Статус и ограничения

Объединены точные зависимости:

- T7 `24fb538473b6f3163cff6698673eab3f63a37c6d`;
- T8 `500d046c2b6a2c02480ae61949d46f6445a636d2`;
- T9 `c3e93598e3849b8ebbc8858be570c55bb4415ef4` (CSS, epoch и focus hooks);
- T10 `f5eefc2d50b0c84807452b3c0759b74d65e959d7`;
- T1 `b024655aa62883e4be2093f8135894a7c5bc0ecc` для карточек и focus helpers.

Финальный прогон `run-Xd8KRv` завершился exit 0: HTTP/экспорт, девять UI-метрик,
проблемы/работы/ресурсы, реальные карточки проблемы/заказа, Back/Escape с точным
возвратом фокуса, loading/error/retry, Tab к JSON, отсутствие кражи перемещённого
фокуса и неожиданных ошибок консоли/страницы. Все три PNG просмотрены.
Сервер, Edge и временный профиль успешно закрыты/удалены самим runner.

Строгая геометрия:

| Задано | innerWidth | clientWidth / scrollWidth | Выступающие элементы |
|---|---:|---:|---:|
| 1280 | 1280 | 1265 / 1265 (scrollbar) | 0 |
| 390 | 390 | 390 / 390 | 0 |
| 414 | 414 | 414 / 414 | 0 |

Целевые тесты harness: 4/4. До последних UI epoch/focus hooks общий `node --test`
на `72a7830e55cda71b022b88d3067e73e47edcbb6d` прошёл 197/197, build OK.
По указанию координатора полный повтор на финальной общей сборке выполняет root;
T11 не выдаёт предыдущий общий прогон за проверку последнего SHA.

Обнаруженное расширение мобильной навигации до 421 px исправлено T9 и покрыто
регрессией harness. Cleanup сохраняет первичную ошибку, всегда пытается закрыть
сервер и удаляет профиль только после подтверждённого выхода Edge. Внутренние
повторы rm отключены (`maxRetries: 0`); максимум пять внешних попыток с 250 мс.
PASS печатается только после cleanup. Старые инфраструктурные сбои запуска Edge
отделены от финального успешного прогона; оставшиеся свои профили очищены.

Ограничения: отдельный межвкладочный reset не входит в этот браузерный маршрут.
Атакующие строки CSV проверяются unit-тестами T8; E2E использует реальные
синтетические названия. Новые улучшения после финального прогона не начаты.
