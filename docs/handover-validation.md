# Проверка центра передачи смены

Все данные сценария синтетические. Исходная база T11: PR45,
`6d03fbf29350a6be23379f81563c28b525ecbccb`. Полный интеграционный результат
нельзя считать пройденным до объединения точных SHA T7–T10 и реального запуска.

## Запуск

```powershell
$env:AI_PROVIDER='local'
$env:HANDOVER_PORT='3054'
node --test tests/e2e-handover.test.mjs
node scripts/e2e-handover.mjs
```

Установленный Edge и нативный CDP/WebSocket Node 24; без npm-зависимостей.
`HANDOVER_BROWSER` — абсолютный путь к Edge. Отсутствующий браузер даёт явный
SKIP, который не означает успешную E2E-проверку. Остальные ошибки дают exit 1.
Занятый порт не переиспользуется, чужие серверы не останавливаются.

Сценарий собирает dist и запускает createApp с отдельным Workshop и local AI.
Он не читает `.env` и существующие сохранения. Уникальный state-файл и профиль
браузера находятся в созданном для запуска временном каталоге. Cleanup в finally
закрывает собственный сервер/браузер и удаляет только этот каталог.
HTTP/CDP ограничены таймаутами; общий предел — 180 секунд.

## Проверяемый маршрут

1. Свежий Workshop: неисправность A1, ремонт, продвижение на 15 минут.
2. `/api/handover`: схема, числа относительно одного snapshot, нули,
   open/unresolved проблемы, queued/running работы, текущие задачи/заказы,
   техники и склад, последние 20 событий seq/type, отсутствие приватных полей.
3. Повторный GET детерминирован и не меняет производство. JSON/CSV: тип, UTF-8,
   attachment и содержимое; некорректный format даёт 400.
4. `#handover` при 1280 и 390 px: сущности/ресурсы, метрики,
   отсутствие горизонтального overflow, снимки экрана.
5. Enter в существующую карточку и browser Back, видимый Tab-фокус.
6. CDP задерживает GET отчёта: loading, искусственный 503, ошибка,
   клавиатурный retry и восстановление содержимого.
7. Нет неожиданных console/page ошибок; просмотр не меняет snapshot.

Артефакты: отдельная ignored `screenshots/handover/run-*/` на каждый запуск —
PNG, JSON, CSV и geometry JSON. Метрики сверяются по девяти фактическим
`data-handover-metric`, включая процентное представление FPY. Искусственный
сетевой 503 допускается только на этапе ошибки. Layout/scroll width сравниваются
с заданной шириной устройства: сравнения только с innerWidth недостаточно,
потому что мобильный браузер может сам расширить layout viewport.

**Финальная адаптивная приёмка пока не пройдена.** Строгий `run-8SGpTO`
обнаружил на 390 px: clientWidth 390, innerWidth/scrollWidth 421; ссылка навигации
выходит до 419.78125 px. При прежнем сравнении с innerWidth это было незаметно.
Дефект передан координатору для T9. 1280 px проходит строгую геометрию.

Cleanup сохраняет первичную ошибку и всегда пытается закрыть сервер. При
неподтверждённом завершении Edge профиль остаётся с явной ошибкой; успешный
финальный PASS печатается только после cleanup. Cross-tab reset ещё не покрыт.
Атакующие строки CSV покрываются unit-тестами T8; этот E2E использует реальные
синтетические названия.

Следующее конкретное улучшение: устранить выступающую аналитическую навигацию
на 390/414 px и повторить строгий E2E без расширения layout viewport.
